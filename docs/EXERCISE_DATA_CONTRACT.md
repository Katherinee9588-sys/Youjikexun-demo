# 有迹可循｜运动字段最终数据契约 v2.0

**交付对象：前端、后端、数据表和大模型提取共同使用。**

本契约依据内部原始记录与最终产品交付。契约只负责把用户说过的运动/活动留下并分类，不用于医疗判断、治疗建议、运动处方或自动推断运动强度。

## 1. 最终字段总表

| 字段名 | 中文名 | 类型 | 是否必填 | 是否多选 | 单位 | 允许值/范围 | 示例 | 空值规则 |
|---|---|---|---|---|---|---|---|---|
| `exercise_type` | 运动类型汇总 | `ExerciseType[]` | 否 | 是 | 无 | `aerobic`、`strength`、`core`、`stretching`、`yoga`、`walking`、`other` | `['strength','aerobic']` | 没有可识别运动时为 `[]`；不生成默认类型。 |
| `exercise_duration` | 运动总时长 | `Int \| null` | 否 | 否 | 分钟 | 1–1440 的整数 | `40` | 用户明确说出总时长，或分别明确说出各项分钟数时才填写；未记录为 `null`；不从组数、步数或“很久”换算。 |
| `exercise_sets` | 单项/明确归属的组数 | `Int \| null` | 否 | 否 | 组 | 1–200 的整数 | `4` | 只有组数明确且整条记录只有一项运动明细时填写；多项运动时为 `null`。 |
| `exercise_details` | 分项运动明细 | `ExerciseDetail[]` | 否 | 是 | 分钟、组 | 见第 2 节 | `[{'type':'core','raw_name':'核心训练','sets':4}]` | 没有可结构化运动明细时为 `[]`；不为无记录日期生成空对象。 |
| `exercise_raw_text` | 运动原始表达 | `String \| null` | 否 | 否 | 无 | 用户语音转写/文字原文 | `早上做了八段锦，傍晚核心训练` | 没有运动相关表达时为 `null`；永远保留，不被结构化结果覆盖。 |

```ts
type ExerciseType = 'aerobic' | 'strength' | 'core' | 'stretching' | 'yoga' | 'walking' | 'other';
type ExerciseDetail = {
  type: ExerciseType;
  raw_name: string;
  duration_minutes: number | null;
  sets: number | null;
};
```

`exercise_details[]` 是多种运动、分项时长和分项组数的可靠保存位置。`exercise_type`、`exercise_duration`、`exercise_sets` 是列表和旧接口使用的汇总字段。

## 2. `exercise_type` 完整枚举

| 字段值 | 中文显示名 | 定义 | 可提取示例 | 不可提取示例 |
|---|---|---|---|---|
| `aerobic` | 有氧 | 明确说有氧、有氧操或跳操。 | 有氧 40 分钟；核心训练 + 有氧操 | 出了很多汗 |
| `strength` | 力量 | 明确说力量、抗阻、负重、举铁或某部位力量训练。 | 轻度力量训练；背部力量训练 | 练得挺累 |
| `core` | 核心 | 明确说核心/核心训练；动作只有在核心上下文明确时归入核心。 | 核心训练 4 组 | 腰部扭转 |
| `stretching` | 拉伸 | 明确说拉伸、伸展、放松动作或某部位拉伸。 | 早晚拉伸；肩颈拉伸 | 活动了一下 |
| `yoga` | 瑜伽 | 明确说瑜伽、瑜伽课或瑜伽练习；“体式”需要瑜伽上下文。 | 睡前瑜伽；瑜伽课 | 做了几个体式 |
| `walking` | 步行 | 明确说散步、快走、步行或走了若干步/圈。 | 晚饭后散步 20 分钟 | 出去转了转 |
| `other` | 其他运动/活动 | 有明确名称但无法稳定归入以上六类；只作回顾标记。 | 八段锦；金鸡独立；足弓训练 | 今天做了点运动 |

### 不新增专属枚举的表达

- 八段锦、拍八虚、托天理三焦、金鸡独立、提踵、足弓训练归 `other`，原始名称必须保留；
- 臀腿、背部是训练部位，不是新枚举；臀腿/背部力量训练归 `strength`，臀腿/背部拉伸归 `stretching`；
- 深蹲、臀桥、鸟狗、平板支撑有明确核心上下文时可归 `core`，有明确力量/抗阻上下文时可归 `strength`，否则归 `other`；
- 慢跑、游泳、骑车、羽毛球、舞蹈当前统一归 `other`，不擅自改写为 `aerobic`；
- 冥想、呼吸练习、欧姆唱诵不属于运动类型；
- 擦地、做家务不自动归为运动。

## 3. 多选、时长和组数

### 3.1 多选

一条记录出现多种运动时，`exercise_type` 保存去重数组，顺序按原话首次出现顺序。“睡前瑜伽拉伸”保存 `['yoga','stretching']`。

### 3.2 时长

- `exercise_duration` 只使用用户明确表达的分钟数，整数范围 1–1440；
- “有氧 15 分钟” → 顶层 `15`，对应 detail 为 `15`；
- “力量 20 分钟、有氧 15 分钟” → 顶层 `35`，details 分别为 `20`、`15`；
- 只说“力量训练和有氧” → `null`；
- “一个小时瑜伽拉伸” → 顶层 `60`；“早晚拉伸” → `null`。

### 3.3 组数

- `exercise_sets` 单独保存，不得塞进时长，也不换算成分钟；
- “核心训练 4 组” → 顶层和 detail 都为 `4`；
- “力量 4 组、核心 3 组” → 顶层 `null`，details 分别保存；
- “核心、力量训练，一共 4 组” → 顶层和 details 都为 `null`，只保留原文；
- “金鸡独立三组，提踵三组” → 两项 details 分别保存，顶层 `null`。

## 4. 枚举外名称规则

采用“允许 `other` + 保留原文”：不拒绝用户输入，不动态增加枚举。

1. 明确名称但不属于六类 → `exercise_type` 加 `other`，detail 的 `raw_name` 保存原名称；
2. 只有“运动了/锻炼了一下/动了一下” → 类型和 details 均为空数组；
3. 结构化失败时 `exercise_raw_text` 仍保存原话，不删除、覆盖或改写原文。

## 5. 验收样例

| 用户原话 | 期望类型 | 期望时长/组数 |
|---|---|---|
| 今天做了核心 4 组和有氧 15 分钟。 | `['core','aerobic']` | duration `15`；顶层 sets `null`；core detail sets `4` |
| 昨晚做了瑜伽拉伸。 | `['yoga','stretching']` | duration/sets `null` |
| 背部力量训练 3 组，背部拉伸 10 分钟。 | `['strength','stretching']` | strength sets `3`；stretching duration `10` |
| 早上八段锦，金鸡独立三组。 | `['other']` | 顶层 sets `null`；保留两个原名与金鸡独立 3 组 |
| 晚饭后快走 20 分钟。 | `['walking']` | duration `20` |
| 今天做了点运动，感觉挺累。 | `[]` | duration/sets `null` |
| 出去转了转。 | `[]` | duration/sets `null` |
| 做了几个体式。 | `[]` | 无瑜伽上下文时不提取 |
| 今天没运动。 | `[]` | duration/sets `null` |

## 6. 空值、缺失和错误

- 没有记录运动：类型和 details 为 `[]`，时长/组数/原始表达为 `null`；
- 记录了运动但没有可识别类型：保留原始表达，类型为 `[]`；
- 记录了类型但没有时长/组数：类型照存，时长和组数为 `null`；
- 缺失日期不创建运动记录，不生成“未运动”、0 分钟或默认活动；
- API/LLM 解析失败不回退到模拟运动数据；原始记录照常保存。

## 7. 前端显示

- 显示名使用“运动类型、运动时长、运动组数、原始记录”；
- `other` 显示“其他运动/活动”，同时展示 `raw_name`；
- 趋势只使用结构化真实数据，未记录日期保持断点，不补 0；
- 冥想不进入运动列表；
- 不生成因果、疾病判断、治疗建议或运动处方。

## 8. 历史字段迁移映射

| 历史字段/表达 | 新字段映射 |
|---|---|
| `cardio_minutes` | `type='aerobic'`，分钟写入 detail；有明确分钟时同步写顶层时长。 |
| `core_sets` | `type='core'`，组数写入 detail；整条只有一个 detail 时才同步顶层组数。 |
| `glute_leg_sets` | `type='strength'`、`raw_name='臀腿训练'`、组数写入 detail。 |
| `back_sets` | `type='strength'`、`raw_name='背部训练'`、组数写入 detail。 |
| `arch_training: yes/no` | `yes` → `other`、`raw_name='足弓训练'`；`no` 不生成类型。 |
| 原文“臀腿拉伸/背部拉伸” | 追加 `stretching` detail，不与力量组数合并。 |

同一条记录有多个运动明细时，顶层 `exercise_sets` 为 `null`，防止把不同项目的组数相加。
